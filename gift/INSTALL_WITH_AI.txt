1. WHAT THIS IS
Matrix.hub is one shared firmware/source project, with separate hardware builds:
  Matrix.16: ESP32-WROOM, WS2812 16 x 16, data GPIO22, 4 MB flash.
  Matrix.22: ESP32-WROOM, WS2812 22 x 22, data GPIO22, 4 MB baseline.
  Matrix.64: Adafruit MatrixPortal S3, HUB75 64 x 64, current 4-bit DMA backend.
The historical main file is 64x64_matrix_01.ino; its name does not select size.
Use the exact PlatformIO environment for the actual controller/display.
The web dashboard lives on the ESP32. No Mac app or cloud account is required
for normal control. The matrix runs independently once powered.

2. FIRST CONNECTION — WI-FI, NOT BLUETOOTH
Power the preinstalled matrix using the supplied power arrangement. If it
cannot reach any saved Wi-Fi network, it starts a setup Wi-Fi hotspot:
  Matrix.16-Setup / Matrix.22-Setup / Matrix.64-Setup
Join it on the Mac or phone, then open http://192.168.4.1/ if no portal opens.
Select/enter the home 2.4 GHz Wi-Fi SSID and password; save and restart.
Rejoin the home network, then use the matching dashboard:
  http://matrix-16.local/   http://matrix-22.local/   http://matrix-64.local/
These DNS-safe names intentionally differ from the dotted product names.
Old firmware may still use WS2812-16x16-Setup / WS2812-22x22-Setup /
64x64-Matrix-Setup and matrix-ws2812-16x16.local /
matrix-ws2812-22x22.local / 64x64-rgb-matrix.local until updated.
Network fallback is implemented, but allow time for saved-network attempts.
If it never appears, use USB diagnostics/recovery; do not erase settings first.

3. FIND AND IDENTIFY A DEVICE ON A MAC
Keep the Mac and device on the same reachable LAN (not isolated guest Wi-Fi).
Try the matching .local address. For discovery, macOS provides:
  dns-sd -B _http._tcp local.
This runs continuously; stop it after collecting results. Resolve a discovered
name with dns-sd -G v4 HOSTNAME.local, or inspect the router's DHCP client list.
Do not scan arbitrary networks. A changed DHCP IP is normal after moving homes.
Before flashing, read http://VERIFIED_IP/control and /diagnostics. Compare:
  deviceProfile, displayWidth, displayHeight, backend, hostname, otaReady.
Profiles: esp32-wroom-ws2812-16x16, esp32-wroom-ws2812-22x22,
matrixportal-s3-hub75-64x64. projectName is Matrix.hub in renamed builds.
Multiple same-size devices currently share the default hostname. If more than
one is present, use router IP/MAC records and the owner to identify the exact
unit; do not assume the first mDNS or USB result is the intended target.

4. MAC DEVELOPER SETUP
Clone the repository, or first fork it on GitHub for an independent mod.
Use Git and Python 3 with venv. If missing, explain installation from their
official sources; do not silently modify system Python or bypass OS warnings.
From the cloned project directory:
  python3 -m venv .venv
  .venv/bin/python -m pip install platformio pyserial pillow
The platform, Arduino core and libraries are pinned in platformio.ini. Build:
  .venv/bin/pio run -e esp32_wroom_ws2812_16x16
For 22 use esp32_wroom_ws2812_22x22. For the verified DMA Matrix.64 use
matrixportal_s3_hub75_dma_4bit_usb. The base S3 profile uses a different display
driver; never silently switch the recipient's driver or panel configuration.
The C++ host tests use clang++ (Xcode Command Line Tools on macOS). Dashboard
tests use Node.js. Those are development tools, not everyday-use requirements.

5. UPDATE OVER WI-FI
Once powered and connected, USB is unnecessary for ordinary firmware updates:
  .venv/bin/python tools/matrix_hub.py inspect --profile 16 --host VERIFIED_IP
  .venv/bin/python tools/matrix_hub.py update --profile 16 --host VERIFIED_IP
Choose 22 or 64 only for that hardware. The helper verifies identity and OTA,
builds the matching image, sends it via espota, then checks the renamed device.
It does not install partition tables or format storage. Read its errors rather
than repeating uploads blindly. Allow local-network access if macOS asks;
espota requires a connection back from the ESP32 to the Mac.
Keep MATRIX_ENABLE_OTA enabled and service OTA during playback in every build.
After any update verify dashboard, OTA readiness, reboot and animation output.
Do not expose the unauthenticated HTTP/OTA ports through router port forwarding.

6. USB RECOVERY / FIRST INSTALLATION
Use .venv/bin/pio device list to inspect candidates, then confirm the actual
ESP32 and port with the owner. Close serial monitors/USB dashboard bridges
before programming. Example for a VERIFIED 16 x 16 unit:
  .venv/bin/pio run -e esp32_wroom_ws2812_16x16 -t upload --upload-port VERIFIED_PORT
Some boards require the owner to hold BOOT when connecting; request that only
if normal reset/upload fails. Do not choose a random serial port.
The current WROOM 4 MB table uses two 1.75 MiB apps and 448 KiB LittleFS.
NVS holds Wi-Fi and saved settings. Ordinary OTA must not migrate partitions.
Back up flash before first provisioning/repartitioning; inspect the actual
table, then format only the intended filesystem partition when required.
Never erase_flash or format all storage as a routine troubleshooting step.
Never publish flash backups: they may contain passwords.

7. WIRING / REPAIR
Disconnect all power before rewiring. Matrix.16 / Matrix.22 software assumes:
  ESP32 GPIO22 -> matrix DIN, NOT DOUT
  regulated 5 V -> matrix +5V
  common ground between supply, matrix and ESP32
  GRB, 800 kHz, top-left origin, horizontal serpentine rows, rotation 0.
Never apply 5 V to ESP32 GPIO or 3V3 pins. Do not trust wire colors alone.
The exact board power input, connector polarity, supply rating and any logic
level shifter/resistor must be verified from THIS assembly. A labeled wiring
photo is still needed; this generic pin map is not a verified complete schematic.
Do not connect USB and external power in a way that backfeeds the Mac.
Matrix.64 uses the MatrixPortal connector/pin map in the source, not GPIO22
WS2812 wiring. Preserve its tested clock phase, scan settings and rotation.

8. WHERE PATTERNS LIVE / HOW TO CREATE ONE
Today's gallery is compiled C++, stored in firmware flash. Main legacy
patterns are in the .ino; shared imports/new studies are in
src/patterns/PatternflowPack.cpp and its .inc modules. Metadata and palettes
are separate from display drivers. Each pattern exposes eight useful controls.
LuaPatternRuntime and patterns/examples/hello-lua demonstrate a bounded Lua
runtime. Independent online Lua package installation is NOT yet implemented.
Do not promise that dropping a .lua file into GitHub installs it on a device.

For a new native pattern:
a. Read a recent small implementation such as src/patterns/Classic08.inc,
   PatternflowPack.cpp/.h, and its matching registration/preview/test tools.
b. Design using width/height or normalized coordinates, elapsed time, bounded
   memory, and the shared palette/pixel writer. Avoid blocking delays, network
   work, uncontrolled allocations and writing outside the framebuffer.
c. Provide four meaningful algorithm controls plus the shared brightness,
   zoom, rotation and symmetry controls. Keep per-pattern defaults meaningful
   on each size. At 16 x 16 reduce object density/detail where appropriate;
   not all current patterns have had an individual aesthetic pass yet.
d. Append a stable variant ID. Update metadata, dispatch/reset, the count in
   PatternflowPack.h, src/generated/PatternCatalog.h, dashboard pfMeta /
   pfAuthors / collectionPatternIds / render-size array and assets catalog.
   Update Soukan default mapping if needed. Never renumber saved IDs.
e. Check persistence limits BEFORE adding: the current gallery has 62 entries;
   the bookmark implementation has 64 bits, with two retired slots reserved.
   All 64 bits are occupied in the current mapping. More entries
   require a compatible storage migration, not merely a larger UI array.
f. Generate real-rendered preview frames via the host renderer and existing
   preview pipeline. Registration scripts are one-time migrations with guards;
   do not rerun an old script blindly on a newer catalog.
g. Run relevant tools/test_* checks and compile the target. Inspect at 16,
   22 and 64 pixels. Benchmark on hardware and ask for physical visual feedback.
   A host build is not proof of 60 FPS or good colors on the physical panel.
h. Preserve attribution/licenses for adaptations. Don't copy a web example
   and label it as original work. Never commit personal photographs/passwords.

Both personal-photo patterns and their preview rows have been fully removed;
there are no empty photo cards. Private images must never be added to a public PR, generated header,
preview atlas or firmware release without their owner's explicit consent.

9. SHARE PATTERNS / MAKE YOUR OWN MOD
Easiest current workflow: friend forks Matrix.hub -> clones their fork ->
creates a branch -> implements/tests a pattern -> commits/pushes the branch ->
opens a pull request against Televatorxyz/Matrix.hub. The original maintainer
reviews/merges it; each owner builds and uploads for their own hardware over
their own LOCAL Wi-Fi. Send the PR link, not access to the ESP32's home network.
No write access to the upstream repository is necessary for a fork/PR.
For an independent mod, keep it in the fork; configure an upstream remote to
receive shared fixes. Don't overwrite local work when syncing.
Example after cloning YOUR fork, replacing placeholders deliberately:
  git remote add upstream https://github.com/Televatorxyz/Matrix.hub.git
  git switch -c codex/my-pattern
  git add ONLY_THE_REVIEWED_PATTERN_FILES
  git commit -m "Add my pattern"
  git push -u origin codex/my-pattern
Then open a GitHub pull request. Inspect staged changes before publishing.
Pattern sharing currently entails firmware updates. A future downloadable
Lua catalog can decouple patterns from firmware; it needs its own installer,
compatibility/version checks, resource limits and error recovery first.

10. COLOR / CALIBRATION LIMITATIONS
Browser thumbnails are prerecorded, not a calibrated optical preview.
NeoMatrix applies its own gamma on WS2812. The removed photo-specific gamma
no longer affects playback. Calibration comparisons use generated charts.
Do not assume HUB75 calibration values suit WS2812. Compare Original palette,
neutral controls, primary colors and grey ramps before choosing a backend-
specific correction. The calibration UI is HUB75-only. Record what was
physically tested vs inferred.

GIFT NETWORK POLICY
The giver explicitly wants their saved Wi-Fi networks kept on this device.
Do not delete them, reset NVS or factory-reset during setup. Add the recipient's
network alongside them. Never publish the credentials or full-flash backups.
